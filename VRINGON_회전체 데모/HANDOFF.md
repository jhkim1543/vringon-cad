# HANDOFF — VRINGON 회전체: 도면 → 파라메트릭 CAD (2026-08-16)

이 문서가 정본이다. 무엇을 왜 이렇게 만들었는지, 어디까지 됐고 수치가 얼마인지, 다음 사람이 무엇부터 하면 되는지.

## 1. 한 줄 요약
"회전체 도면 → DSL → CAD" 를 **계약(스키마) → 실행기 → 합성 데이터 → 판독기 → 검증 루프 → UI** 순서로 만들었다.
판독(AI)은 모듈 경계 뒤에 있고, 나머지는 전부 결정론이라 **AI 가 틀리면 검증기가 잡고, AI 가 없어도 데모는 돈다.**
골든 12종 기준: 시각 LLM 판독(텍스트 티어 + 실루엣 힌트 + 수리 1회) **세그먼트 F1 100% · 피처 F1 96% · 치수 일치 98% · 실루엣 IoU 1.000 · 완전 일치 58%**, 실행기 유효율 100%.

## 2. 지시서 대비 방법론 분석 — 무엇을 그대로 두고 무엇을 바꿨나

받은 지시서(M0~M5)의 5원칙(계약 우선·역순 구축·골든 파일·수치 합격선·VLM 은 인터페이스 뒤)은 그대로 따랐다. 최근 기술과 본체 데모에서 얻은 교훈으로 **다섯 가지를 바꾸거나 더했다.**

| 지시서 | 여기서 한 것 | 이유 |
|---|---|---|
| VLM few-shot 이 판독의 전부 | **실루엣 결정론 판독기를 앞단에** 두고 그 측정을 VLM 힌트로 준다 (Point2CAD/CAD-Recode 류의 "측정 우선" 사고를 2D 에 적용) | 본체 데모 v13 교훈: 이미지→언어→좌표 전사 손실이 가장 크다. 실루엣 r(x) 는 픽셀에서 바로 나오고 비율은 IoU 0.997 로 정확하다. VLM 은 구조를 여기에 맞추고 문자(치수·나사·공차)만 읽으면 된다. 서버가 없어도 이 판독기로 데모가 돈다. |
| 검증 = 재렌더링 실루엣 IoU + 치수 재추출 | IoU 는 **래스터 없이 r(x) 표본으로 해석적으로**(회전체는 축대칭이라 IoU=Σmin/Σmax 가 정확), 치수 대조는 **모델이 읽었다고 보고한 문자열(dims_read)** 을 DSL 과 대조 | 빠르고(ms) 브라우저·서버·Node 어디서나 같은 코드. dims_read 는 "읽었는데 반영 안 한 값"을 드러내 수리 루프의 근거가 된다(CADCodeVerify 류의 검증-수리 사고). |
| 실행 실패 시 1회 재생성 | 수리 트리거를 셋으로: **실행기 오류 / 실루엣 IoU<0.85 / 치수 정합<0.9** — 각각의 증거를 프롬프트에 넣고, 수리본이 더 나을 때만 채택 | 실측: 12종 중 4~6종에서 발동, 신뢰도가 오를 때만 채택되어 회귀가 없다. |
| 응답 스키마 제약 | 응답 스키마의 **모든 키를 required** 로(해당 없음은 0/빈 문자열, 서버가 걷어냄) | 제약 디코딩이 선택 키를 통째로 생략하는 실측 현상(모델이 notes 에 "홈 offset 12.7 로 환산" 이라 쓰고 grooves 는 [] 를 낸다). required 로 바꾸자 피처 F1 25% → 96%. |
| CadQuery 실행기가 유일한 실행기 | 브라우저 실행기(three.js 밴드 lathe + 국부 CSG)를 **같은 프로파일 함수** 위에 하나 더 두고, 파이썬 실행기는 해석적 STEP/USDA 담당 | 데모는 즉시 반응해야 하고(수십 ms), 파라미터 편집이 3D·도면·검증에 동시에 반영돼야 한다. 두 실행기의 프로파일은 골든 테스트가 1e-6 로 묶는다. |

바꾸지 않은 것: DSL 을 유일한 표현으로 강제, 골든 파일 회귀, 합격선 수치화, 합성 데이터가 물량의 원천, USD 에 파라미터 어태치.

### 참고한 최근 흐름 (벤더명 없이)
- 도면→CAD 시퀀스 생성: Drawing2CAD(2025, CAD-VGDrawing), Text2CAD, CAD-Coder 류 — "출력은 실행 가능한 프로그램/시퀀스" 라는 점을 DSL 로 채택.
- 측정 우선 역설계: CAD-Recode(포인트→코드), Point2CAD — 좌표는 측정으로, 언어는 의미로.
- 생성-검증-수리 루프: CAD-Assistant/CADCodeVerify 류 — 실행기·렌더러 피드백을 프롬프트로 되돌림.
- 합성 도면 증강: CMU 의 치수 무작위화 합성(Data-Augmentation-Engineering-Drawing) — 여기선 표준 규격표 기반 샘플러 + 치수 생략·스캔 열화.
- 이 프로젝트의 본체(vringon-cad) 교훈: 실루엣 IoU 를 목적함수로, LLM 은 좌표를 만들지 않게, 지시만 하고 검증하지 않으면 지켜지지 않는다.

## 4. 아키텍처 (데이터 흐름)
```
도면(PNG/JPG/SVG) ─┬─► 실루엣 측정(브라우저) ── r(x)·세그먼트 초안 ── 힌트 ─┐
                   │                                                      ▼
                   └─────────── 이미지 ──────────► /api/extract 시각 LLM(스키마 제약·few-shot 3) ── DSL, dims_read
                                                          ▲                       │
                                                          └── 수리 프롬프트 ◄── 검증(스키마·기하·IoU·치수 정합) ─ 신뢰도
DSL ─► shaft-profile(반단면) ─┬─► shaft-cad(three.js) ─► 뷰어 · STEP(면분할)/STL/GLB/OBJ/USDA
                              ├─► shaft-drawing ─► SVG/DXF 도면 · 검증용 r(x)
                              └─► pipeline/executor.py(CadQuery) ─► STEP(해석적)/STL/USDA   (서버 /api/step · 샘플은 미리 생성)
```
- **좌표 규약**: 축 = X, 왼쪽 끝 x=0. `transitions[].at` 은 경계 번호(0=왼쪽 끝, n=오른쪽 끝). 비축대칭 피처 `angle` 0°=+Z(정면 관찰자), 90°=+Y.
- **정적/라이브**: `index.html` 이 `/api/status` 로 감지. 정적(Pages)에서는 샘플의 `extracted.json` 재생 + 업로드/합성은 실루엣 판독. 라이브에서는 시각 LLM.
- **키·벤더**: `../config.local.json` 의 primary/fallback/… 역할명만. 코드·문서·리포트에 벤더명 없음(본체 정책 동일).
- **텔레메트리**: 라이브 판독은 `data/telemetry.jsonl` + `data/uploads/<hash>` 로 SFT 쌍이 쌓인다(gitignore).

## 5. 수치 (eval/, 2026-08-16, 골든 12종)
| 판독기 | 유효율 | 세그먼트 F1 | 피처 F1 | 전이 F1 | 홈 F1 | 치수 일치 | IoU | 완전 일치 | 평균 시간 |
|---|---|---|---|---|---|---|---|---|---|
| 실루엣(결정론, 브라우저) | 100% | 71% | 42% | 66% | 58% | 73% | 0.997 | 8% | ~0.2 s |
| 시각 LLM 텍스트 티어 + 힌트 + 수리 | 100% | 100% | 96% | 100% | 83% | 98% | 1.000 | 58% | 17.7 s |
| 시각 LLM 설계 티어(thinking) + 힌트 + 수리 | 100% | 100% | 94% | 100% | 83% | 97% | 1.000 | 67% | 39.7 s |

- 실루엣 판독기의 IoU 0.997 은 "비율은 정확, 절대치·의미(나사 피치·센터구멍·공차)는 못 읽음" 을 뜻한다. 그래서 VLM 힌트로 딱 맞다.
- 완전 일치를 깎는 잔여 오류: 키홈 위치(세그먼트 끝 기준 치수의 환산), 단일 평면 깊이(D−depth 를 두 면 대변으로 오해), 도피홈 수치. 프롬프트 규칙 6·10 을 손보거나 설계 티어를 쓰면 줄어든다.
- 재생용 `samples/<id>/extracted.json` 은 마지막으로 `--save` 로 돌린 티어의 결과다(현재: 설계 티어, 2026-08-16). 두 티어의 차이는 완전 일치 58%→67%뿐이라 라이브 기본값은 빠른 텍스트 티어, '정밀 판독' 체크박스가 설계 티어다.

## 7. 알려진 한계 · 주의
- 실루엣 판독기는 **정면도가 가로로 놓인 깨끗한 도면** 가정. 다중 투상도(정면+측면)가 나란히 있으면 가장 넓은 성분을 정면도로 잡는다. 사진·손그림은 임계값(105)에 걸릴 수 있다 → 업로드 시 "전체 길이" 입력이 축척을 정한다.
- 브라우저 실행기의 밴드 경계에는 내부 캡 면이 남는다(렌더에는 안 보이고 단면 보기에서 부채꼴로 보임). STL/GLB 는 각 밴드가 닫힌 솔리드라 프린팅엔 문제없고, 해석적 STEP 은 파이썬 실행기가 단일 솔리드로 만든다.
- 필렛·라운드는 폴리라인 근사(10분할). 파이썬 실행기에서 토러스 면이 필요하면 프로파일 태그(`fillet_arc`) 구간을 `threePointArc` 로 바꾸면 된다.
- 나사·널링은 관례대로 장식(형상 없음). 규격은 DSL·USDA 속성·STEP 이름에만.
- 응답 스키마 노드 수 105 — 1차 LLM 한도(본체 실측 250) 아래. 필드를 늘릴 때 `node -e "import('./tools/extract-prompt.mjs')…"` 로 노드 수를 세어 둘 것.
- 시각 LLM 이 없으면(정적) 업로드는 실루엣 판독만 — UI 가 그렇게 말한다. 정직성 원칙: 대역을 실제 출력이라고 쓰지 않는다.

## 8. 다음 사람이 할 일 (우선순위)

## 10. 2차 (2026-08-16 오전) — 외부 도면 업로드 실패 분석과 보강

### 10.1 왜 캐스터·어댑터 도면이 안 됐나 (실측)
사용자가 올린 두 장은 (a) 캐스터 조립체 3면도(450px JPEG), (b) 플랜지 어댑터(등각 그림 + 볼트 원 구멍·슬롯 부품도).
- **범위 밖**: 이 데모는 선반 회전체 한 부품의 정면도를 읽는다. 캐스터는 바퀴·포크·플레이트·브레이크의 조립체이고, 어댑터는 회전체이지만 **볼트 원 위 축방향 구멍과 슬롯**이 DSL v1.0 에 없다.
- **정적 모드 = 실루엣 판독**: 문자를 읽지 않고 굵은 외형선만 남겨 r(x) 를 잰다. 3면도가 위아래로 놓이면 정면도+평면도 두 성분을 "전단면의 거울상 두 반쪽" 으로 오인해 존재하지 않는 보어(⌀85 > 외경 ⌀43.5)를 만들었고, 실행기 검증이 그걸 잡아 빨간 오류로 나온 것이 스크린샷의 상태다.
- **저해상**: 부품 폭 145px 수준에서는 외형선(2px)과 치수선(1px)이 붙어 세그먼트가 20개로 쪼개진다.
- **고친 것**: ① 거울상 짝 판정에 높이 유사성(±35%)과 "안쪽 띠가 외경의 92% 이상이면 별개 뷰" 조건 추가 ② 다중 투상도·저해상·과분할 신호를 `flags/reasons` 로 올리고 UI 가 "회전체 정면도답지 않음 + 안내 링크" 를 먼저 보여 준다 ③ 시각 LLM 프롬프트에 [적합성] 절 — 회전체가 아니면 `segments: []` + "회전체 아님: 이유" 를 내고 서버가 `not_revolve` 로 돌려준다(실측: 캐스터 삽화 → "회전체 아님: 바퀴·브래킷·상부 플레이트·브레이크가 결합된 캐스터 조립체").

### 10.2 업로드 안내 (guide.html)
`guide.html` — 되는/안 되는 도면 삽화 7장(폴백 LLM 이미지 모델로 생성, `tools/gen-guide-images.mjs`, 메타데이터 제거 후 webp), **치수 기준 그림은 렌더러가 그린 실제 도면 위에 번호를 얹은 것**(`tools/gen-guide-annot.mjs` → `assets/guide/dim-guide.webp` + 범례 JSON) — 이미지 모델이 그린 숫자는 정확하지 않아서다. 파일·해상도 체크리스트, 판독 방식(정적/온프렘)과 OCR 설명, 지원/미지원 형상 표, 내려받기 형식 표. 드롭존과 실패 안내에서 링크한다.

### 10.3 OCR 은?
- 온프렘: **시각 LLM 이 치수 문자를 전부 읽어 `dims_read` 로 근거를 남긴다** — OCR + 의미 해석을 한 번에 하는 셈이고, DSL 과 대조해 안 맞으면 수리 라운드를 돈다. 별도 OCR 엔진은 없다.
- 정적(Pages): 문자를 읽지 않는다 → 실루엣 비율 + "전체 길이" 입력. **다음 단계**: 브라우저 OCR(Tesseract.js, 자체 호스팅 ~8MB: 코어 wasm + eng.traineddata) 로 치수 숫자를 읽어 실루엣 세그먼트에 위치 기반으로 배정(부품 아래 줄 = 연쇄 길이, ⌀ 붙은 수직 문자 = 지름, M = 나사). 온프렘엔 PaddleOCR 서버 옵션. 저장소 용량과 폐쇄망 원칙(외부 CDN 금지) 때문에 이번엔 넣지 않았다.

### 10.4 나사류 (볼트·스크루·스터드) — 됨
- DSL 에 `hex_socket`(끝면 육각 렌치 구멍: end·across_flats·depth) 추가 — 스키마·프로파일(부피)·3D(CSG)·도면(숨은선+호출)·검증·프롬프트·파이썬 실행기까지 한 번에. 접시머리 = taper, 육각 머리 = cyl + hex, 캡 스크루 = cyl + hex_socket, 세트 스크루 = thread + hex_socket, 스터드 = 양끝 thread.
- 샘플러 아키타입 5종(hex_bolt·socket_cap_screw·set_screw·countersunk_screw·stud, ISO 4014/4762/4026/10642 근사 표) + 골든 5종(`hex-bolt-m10`·`socket-cap-m8`·`set-screw-m6`·`countersunk-m6`·`stud-m12`) → 샘플 17종.
- **실측 (`eval/report-screws-text.md`, 시각 LLM 텍스트 티어)**: 5/5 완전 일치(세그먼트·피처·전이·치수 100%). 실루엣 단독은 나사부를 원통으로 읽어 세그먼트 F1 0%(비율 IoU 0.98) — 나사 여부는 문자에서만 알 수 있다는 뜻.

### 10.6 파라메트릭 수정 ↔ 도면·3D (분석과 결정)
- 원본은 **DSL** 이다. 세그먼트 표/JSON 을 고치면 3D·재생성 도면(SVG/DXF)·검증(IoU·치수 정합)이 즉시 다시 계산된다 — 이 방향은 결정론이라 정밀도 손실이 없다(3D 는 실행기, 도면은 렌더러).
- **올린 도면 이미지 → DSL** 방향은 판독 단계에서만 한 번 일어나고 정밀도가 완전하지 않다(골든 기준 완전 일치 58~67%). 그래서 **양방향으로 두지 않고 한 방향(DSL → 3D·도면)만 반영**한다: 원본 이미지는 고치지 않고 그 위에 판독 외형을 겹쳐 보여 주며, "재생성 도면" 토글이 지금 DSL 로 다시 그린 도면을 보여 준다(`btnRegen`). 편집 후 원본 대비 IoU 가 떨어지는 것이 곧 "원본과 달라진 양" 이다(실측: 세그먼트 길이 8→12 수정 시 IoU 1.00→0.887).
- 원본 래스터를 직접 고치는 기능은 정밀도가 낮아 제외했다(치수 문자 재배치·선 재작성은 렌더러 재생성이 정답).

## 11. 조립·시뮬레이션 (2026-08-16, v35) — 도면에서 "도는 곳·빠지는 곳" 읽기

### 11.1 무엇이 가능한가 (분석 결론)
회전체 단품 도면에는 **상대 부품과의 결합부가 규격 표기로 이미 들어 있다.** 그래서 AI 없이 결정론 규칙만으로
"무엇이 어디에 붙고, 어느 방향으로 빠지며, 무엇이 도는가" 를 읽을 수 있다. 판정 근거와 정밀도:

| 판정 | 도면 근거 | 정밀도 |
|---|---|---|
| 자전축 | 회전체 형상 자체(축 대칭). 근거 강도는 센터구멍(DIN 332)·베어링 자리 공차·키홈으로 올라간다 | **정확** — 축은 X 로 정의상 확정 |
| 베어링 | 세그먼트 공차 h5~m6 + "베어링 자리" 라벨. 속이 빈 부품(부시·슬리브)의 외경 공차는 **하우징 압입**으로 따로 판정 | 위치·폭 자리 정확 / 베어링 외경·폭은 6000·6200 계열 근사 |
| 멈춤링 | 홈 ⌀·폭 + DIN 471 표기 | 홈 위치·치수 정확 / 링 외경 근사 |
| 키·허브 | 키홈 폭·깊이·길이 + DIN 6885 | 키 치수 정확(t1 는 표) / 허브 외경은 축경 비례 근사 |
| 너트 체결 | 나사 호칭·피치 (자유단일 때만 너트) | **이송 정확**(1회전 = 피치) / 너트 대변·높이는 ISO 4032 근사 |
| 핀 | 횡구멍 ⌀·위치·관통 여부·각도 | 정확 |
| 공구 | 육각 대변 / 육각 소켓 / 평면 | 정확(치수), 공구 형상은 상징 |
| 끼워맞춤 | 보어 ⌀·H7 등 / 테이퍼 기울기 | 정확 / 상대 축·허브 길이는 근사 |

운동 방향은 전부 회전체 기하에서 나오므로 **정확**하다: 자전 = X축, 축방향 조립 = ±X, 링·키·핀 = 반경 방향, 나사 = 회전+피치 이송.
근사인 것은 상대 부품의 절대 치수뿐이고, UI 에서 "규격 근사" 태그와 반투명 색으로 구분해 표시한다.

### 11.2 구현
- `js/shaft-mates.js` — DSL → `{kind, x, x1, part, params, motion, evidence[], confidence, approx}` + 분해 순서(링→핀→너트/공구→베어링/끼워맞춤→키) + 조립 점검(멈춤링 물림 깊이, 키 돌출, 너트 체결 회전수, 베어링 자리 길이).
- `js/shaft-assembly.js` — 상대 부품 3D(멈춤링 C형 링·평행키·반투명 허브·베어링 3링·육각 너트·핀·육각 렌치·스패너·하우징·상대 축·테이퍼 허브) + 시뮬레이터(분해 슬라이더 0~1 순차 애니메이션, 자전 rpm, 나사 체결 왕복).
- UI 5단계 "조립 · 시뮬" 신설(내보내기는 6단계): 시뮬 도크(회전·나사 체결·조립·정지·분해 슬라이더·rpm), 오른쪽에 결합부 목록(근거·신뢰도, 마우스 오버 시 해당 부품 강조·자전축 점선), 분해 순서, 조립 점검. 내보내기에 "상대 부품 포함" 체크박스(모든 형식, 실측 OBJ +16%).
- 회전 규약: 축과 함께 도는 것(키·허브·링·핀·상대 축)만 회전하고 **베어링은 내륜만**, 스패너·하우징은 고정.

### 11.3 검증 (`node tools/test-assembly.mjs`, 17/17 PASS)
결합부 종류 기대치 일치 · 분해 후 전 부품 이동(>5mm)·조립 시 원위치 복귀(<1e-9) · 자전 각도와 회전/비회전 분리 · **나사 이송 = 피치**(M10 실측 10.08회전 → 15.12mm = 1.5mm/회전).
브라우저 실측(모터 축): 상대 부품 4개(베어링2·멈춤링·키/허브), 분해 31/31/13.5/9.6mm, 자전 600rpm 시 부품·키·베어링 내륜 31.42rad 동일, 베어링 외륜 0.

### 11.4 한계
- 상대 부품은 **규격 근사**다(도면에 없는 치수). 실제 조립 검증(간섭·공차 누적)에는 실제 부품 모델이 필요하다.
- 물리 시뮬레이션이 아니라 **기구학 애니메이션**이다(질량·마찰·강성 없음). 회전 속도는 시각용이고, 위험 회전수·베어링 수명 같은 계산은 넣지 않았다.
- 결합부는 이 DSL 이 표현하는 피처에서만 나온다: 스플라인·세레이션·벨트 홈·기어 이는 아직 DSL 에 없으므로 판정도 없다.
- 개발용 `/__save`(루프백 전용 화면 저장)는 QA 스크린샷용이며 공개 정적 배포에는 서버가 없어 동작하지 않는다.

### 11.5 "회전이 안 도는 것처럼 보인다" (v36, 2026-08-16)
사용자가 플랜지 부시에서 회전 시뮬을 켰는데 화면이 멈춘 것처럼 보였다. 확인 결과 **로직은 정확**했다
(슬라이더 510 rpm → 측정 510 rpm, `__vringon.forceRender(1/60)` 수동 적분으로 검증).
원인은 둘이고 둘 다 표시 문제였다.

1. **회전체는 축대칭이라 자전해도 픽셀이 그대로다.** 키홈·평면·구멍이 없는 부시·스페이서·핀은 돌아도 화면이 100% 동일하다.
   → 부품에 **기준 표시(marker)** 를 붙였다: 외형선을 그대로 따라가는 주황색 띠(각도 6.4°) + 왼쪽 끝면 반경선 + 오른쪽 끝 화살.
   `model` 의 자식이라 같은 회전을 따라가고, `marker:` 이름·`userData.isMarker` 로 **모든 내보내기에서 제외**된다(실측: 삼각형 수 불변).
   상수 반경으로 만들면 단차 부품에서 띠가 공중에 뜬다 → `buildTopLine` 프로파일을 따라 만든다(플랜지 부시에서 실제로 겪음).
2. **숫자 계기가 없었다.** 시뮬 도크에 `510 rpm · 4.3 회전 · 90°`(자전) / `체결 1.8 회전 · 2.67 mm`(나사)를 200ms 주기로 표시한다.
   두 값은 **같은 기준**(체결해 들어간 양)이어야 한다 — 처음엔 회전수를 남은 거리로 재서 비율이 피치와 안 맞았다(0.221 vs 1.5).
   지금은 `advance/pitch` 로 계산해 항상 피치와 일치한다.
3. 덤으로 **조립체 등장 시 카메라 재프레이밍**(`fitAssemblyView`)을 넣었다 — 하우징·허브가 부품보다 커서 화면 밖으로 나가던 문제.

참고: 브라우저 탭이 가려지면 rAF 가 멈춰 회전이 0 으로 보인다(브라우저 정상 동작). QA 는 `__vringon.forceRender(dt)` 로 수동 적분한다.

### 11.6 흐름에서 뺀 둘 (v37, 2026-08-16)
사용자 요청으로 스텝퍼를 **4단계(도면 입력 → 판독·DSL → 3D CAD → 검증)** 로 줄였다.
- **내보내기**는 단계가 아니다 — 3D 가 만들어지는 순간 오른쪽 패널에 목록이 뜨고 계속 남는다(`showExportPanel`).
  DSL 을 고치면 목록도 다시 그린다(정답 STEP 해당 여부·조립 포함 옵션이 바뀌므로).
- **조립·시뮬**은 뷰포트 우상단 토글(`btnSim`)이다. 켜면 상대 부품·기준 표시·시뮬 도크·결합부 패널이 붙고,
  **끄면 전부 걷어내고 부품만 남는다**(회전각 0 으로 리셋, 카메라도 부품 기준으로 재프레이밍).
  이전에는 5단계로 들어가면 상대 부품이 계속 남아 "3D 파일만 보는 상태"로 돌아갈 수 없었다.
- 내보내기 목록에 STEP 이 세 줄(미리 만든 해석적 / 서버 해석적 / 브라우저 면분할) 나오던 것을 정리했다:
  해석적은 한 줄(라이브 서버가 있으면 서버, 없으면 미리 만든 파일), 면분할은 `STEP·면분할` 로 이름을 달리했다.

## 12. 외부 공유 준비 (v38, 2026-08-16)

외부에 링크를 주기 전에 세 가지를 손봤다: **화면 문구**, **첫 사용 안내**, **배포본 보호**.

### 12.1 문구 규칙
사용자에게 보이는 말에는 **알고리즘·라이브러리 이름을 쓰지 않는다**. 두 가지 이유가 겹친다 —
처음 보는 사람에게 뜻이 없고(데모는 결과를 보여 주는 자리다), 우리 구성 요소를 그대로 알려 주는 일이기도 하다.

| 바뀐 말 | 이전 |
|---|---|
| 판독 · 사양 / 치수 사양 | 판독 · DSL / 파라메트릭 DSL |
| 도면 외형 일치 99.0% | 실루엣 IoU 0.990 |
| 세그먼트·피처 일치 | 세그먼트 F1 · 피처 F1 |
| 3D 형상을 만듭니다 | 회전(lathe) + 국부 CSG 로 컴파일합니다 |
| 정밀 곡면 · 기계 CAD 용 | 해석적 B-rep · 파이썬 실행기(CadQuery) |
| AI 판독 / 미리 판독한 결과 | 시각 LLM(스키마 제약 + few-shot) / 온프렘 |
| 외형 판독 | 실루엣 판독 |

문장 안의 `—`·`→`·`↔` 도 뺐다(값이 비어 있음을 뜻하는 `—` 표시는 남는다). 규격 이름(DIN 471, ISO 4032, H7)은
정보가 있으므로 남긴다. 코드 주석은 그대로다 — 배포본에서는 어차피 지워진다(12.3).

### 12.2 첫 사용 안내 (`js/tour.js`)
처음 열면 **사용 순서대로 여섯 자리**를 짚는다: 샘플 → 업로드 → 단계 표시 → 다음 단계 버튼 → 보기 전환/조립·시뮬 → 오른쪽 결과·내려받기.
아직 화면에 없는 버튼(3D 전에는 숨어 있는 토글 등)은 **대체 영역**을 짚는다(`fallbackBox`). 본 것은 `localStorage` 에 기억하고,
상단 "사용법" 으로 언제든 다시 연다. 클릭·Enter·→ 로 진행, Esc·건너뛰기로 닫는다.

### 12.3 보호 빌드 (`tools/deploy-docs.mjs`, 기본값)
`docs/revolve` 로 나가는 것이 바뀌었다: 11개 모듈 + vendor 를 그대로 복사하던 것을 **한 파일(862KB)로 묶고 최소화**한다.
- 주석 전량 삭제(설계 의도·판정 근거·함정 기록이 사라진다), 이름 뭉갬, 소스맵 없음, `importmap` 제거.
- `/* qa:start */…/* qa:end */` 사이의 QA 훅(`window.__vringon`)을 빌드 시 잘라낸다 — 배포본에서 내부 상태를 만질 수 없다.
- 폰트는 CSS 가 직접 부르므로 `vendor/fonts` 만 따로 복사한다(빠뜨리면 404, 실제로 겪음).
- 크기 11.4MB → 9.3MB, JS 는 11.4MB → 0.86MB.
- `--raw` 로 예전 방식(원본 복사)도 남겨 뒀다. 디버깅 전용.

한계는 분명하다: **브라우저에서 도는 코드는 원리상 읽을 수 있다.** 그래서 판독 프롬프트(`prompts/`, `tools/extract-prompt.mjs`)와
API 키는 애초에 배포본에 넣지 않는다. 자세한 판단 근거와 더 세게 막는 선택지는 [DEPLOY.md](DEPLOY.md) 에 적었다.

### 12.4 도메인 배포 (`deploy/`)
- `Dockerfile` — 서버가 실제로 쓰는 파일만 담고, 브라우저로는 **보호 빌드만** 내보낸다(`VRINGON_STATIC`).
- `docker-compose.yml` + `Caddyfile` — 도메인 한 줄로 인증서 자동 발급·갱신.
- 서버에 붙인 것: 환경변수 설정(`VRINGON_PRIMARY_*`, 파일 없이도 뜬다), **접근 코드**(`VRINGON_ACCESS_CODE`, 없으면 공개),
  **주소당 시간 제한**(`VRINGON_RATE_PER_HOUR`, 기본 30 — 판독은 호출당 비용이 든다), 정적 루트 분리.
- 정적만 도메인에 붙일 거면 `docs/CNAME.disabled` → `docs/CNAME`(`cad.rebuilder.ai`) + DNS CNAME 한 줄이면 끝난다.

## 13. 회전체가 아닌 도면을 올렸을 때 (v39, 2026-08-16)

사용자가 **캐스터 조립도(3면도)** 와 **신발 밑창 도면(3면도)** 을 올렸더니, 데모가 경고만 띄우고 도면과 무관한
버섯 모양·계단 축을 만들어 냈다. 원인은 두 겹이다.

### 13.1 왜 그런 결과가 나오나
체험 모드의 판독기는 **문자를 읽지 않는다.** 하는 일은 하나뿐이다 — 굵은 외형선만 남기고, 가장 큰 성분의
위·아래 외곽을 재서 `r(x)` 를 만들고, 그 `r(x)` 를 축 둘레로 돌린다. 그래서 무엇을 넣든 "돌린 것" 이 나온다.
캐스터 정면도를 넣으면 바퀴(반지름 큰 원)와 상판(납작한 판)이 하나의 `r(x)` 로 평균돼 버섯이 되고,
치수가 `R·A·H·B·L·L1` 처럼 **문자 기호**뿐이라 절대 치수도 정할 수 없어 전체 길이 100mm 로 가정한다(재생성 도면의 ⌀58.5 따위는 그래서 나온 값이다).

측정으로 확인한 수치(캐스터 합성 표본, 1100~3400px):
| 값 | 캐스터 | 정상 도면 60건 |
|---|---|---|
| 축 위·아래 모양 차이 | 0.29 | 중앙 0.003 |
| 원통(평탄) 구간 비율 | 0.30 | 중앙 0.95 |
| 세그먼트 수 | 12~14 | 1~8 |

### 13.2 고친 것 — 확실하면 멈춘다
`js/shaft-extract.js` 에 **hard 신호** 셋을 넣고, 하나라도 걸리면 `verdict: "not_revolve"` 로 판독을 **중단**한다
(이전에는 경고만 하고 3D 까지 만들었다). 화면에는 이유와 함께 "그래도 읽어 보기" 버튼을 준다.

| 신호 | 조건 | 잡는 것 |
|---|---|---|
| `asymmetric` | 큰 성분 2개 이상 + 위·아래 둘 다 보이는 열 55% 이상 + 모양 차이 25% 초과 | 조립체(캐스터), 비회전 부품 |
| `circle_view` | 축방향/직각 길이비 < 1.35 + 반원 곡선 오차 < 0.12 | 정면에서 본 원(플랜지 볼트원 도면) |
| `organic` | 세그먼트 8개 이상 + 원통 구간 45% 미만 | 밑창·바퀴처럼 계속 굽은 윤곽 |

기준값은 **정상 60건(샘플 17종×3해상도 + 열화 스캔)에서 오거부 0건**이 되도록 잡았다. `tools/test-input-guard.mjs`
가 이것을 고정한다(음성 표본 3종은 `tools/fixtures/negative-*.svg`, 3해상도 중 2회 이상 차단해야 통과).
서버(AI) 판독에는 이미 `not_revolve` 경로가 있었고, 여기에 "치수가 문자 기호뿐인 카탈로그 도면" 규칙을 더했다.

### 13.3 다중 투상도는 지원하지 않는다 (설계상)
한 장에 정면·측면·평면이 같이 있으면 읽지 못한다. 이 데모의 계약이 **"회전체 한 부품 + 정면도 한 장 → 회전 프로파일"** 이기 때문이다.
다중 투상도를 제대로 읽으려면 (1) 뷰 분할, (2) 각 뷰의 역할(정면/측면/평면) 판정, (3) 뷰 사이 대응점 맞추기,
(4) 정투상 세 장에서 3D 복원 — 즉 지금과 다른 시스템이 필요하다. 다만 **키홈 단면 A-A 처럼 보조 단면이 옆에 있는 것은 지금도 괜찮다**
(가장 넓은 성분을 정면도로 고른다).

## 14. 실제 도면은 한 장이 아니다 — 측정과 다음 단계 (v40, 2026-08-16)

### 14.1 없는 치수를 지어내지 않는다
전체 길이를 입력하지 않으면 100mm 로 가정하던 것을 **중단**으로 바꿨다. 화면의 ⌀58.5 같은 값을
"도면에서 읽은 값" 으로 오해하게 만드는 것이 가장 나쁜 실패다.
- 외형 판독인데 전체 길이가 없으면 → 안내 + [전체 길이 넣기] / [비율만 보기].
- AI 판독인데 **치수 문자를 하나도 못 읽었으면** → 같은 안내(그 숫자들은 근거가 없다).
- 비율만 보기를 고르면 `meta.scale = "assumed"` 를 달고 모델 패널이 `100 mm (비율)` 로 표시한다.

### 14.2 "뷰를 나눠서 프로파일 뷰만 고르면 되지 않나" — 재 보니 반만 맞다
연결 성분을 근접도로 묶어 뷰를 나누고, 각 뷰에 회전 프로파일 점수(대칭도·평탄 비율·가로세로비·잉크량)를 매겨 봤다
(`data/tmp/diag-views.mjs`, 2000px 기준):

| 도면 | 뷰 | 최고 점수 뷰 | 판정 |
|---|---|---|---|
| 샘플 stepped-shaft | 2 | 정면도 0.86 | 맞게 고른다 |
| 플랜지 3면도 | 3 | 측면 단면 0.90 (원형 뷰 0.87) | **맞게 고른다** — 지금 못 읽는 것을 읽게 된다 |
| 신발 밑창 3면도 | 3 | 0.61 | 전부 낮음 → 거부 |
| 캐스터 3면도 | 3 | **평면도 0.97** | **함정** — 위에서 본 판을 "완벽한 회전 프로파일" 로 본다 |
| 샘플 flanged-bushing | 2 | 0.40 | 거울상 반쪽이 두 뷰로 쪼개짐 → 짝 병합이 먼저 필요 |

즉 기하만으로는 **"무엇을 위에서 본 것인지" 를 알 수 없다.** 뷰 분할은 필요조건이지 충분조건이 아니고,
그 앞에 **도면 유형·뷰 역할 판정(정면/평면/측면)** 이 있어야 한다. 이것은 AI 가 할 일이고(문자·표제란·투상 관계를 본다),
실행은 지금처럼 결정론 코드가 한다.

### 14.3 단계별 계획
| 단계 | 하는 일 | 필요한 것 | 지금 대비 |
|---|---|---|---|
| 0 (완료) | 근거 없는 치수 금지, 회전체 아닌 도면 차단 | — | v39·v40 |
| 1 | 뷰 분할 + 역할 판정(AI) → 프로파일 뷰만 읽기. 거울상 짝은 먼저 병합 | 뷰 상자를 AI 힌트로 전달, 역할 응답 스키마 | 플랜지·다중 투상도 지원 |
| 2 | 원형 뷰에서 볼트원·축방향 구멍 읽기 | DSL 확장 `axial_holes`, 원형 뷰 판독 | 플랜지·커버·풀리 |
| 3 | 표제란·공차·거칠기·기하공차를 사양에 싣기 | 텍스트 블록 판독 + 스키마 확장 | 제작 정보 완결 |
| 4 | 조립도: 부품 인스턴스 분리 → 부품별 실행기(revolve/extrude/sheet-metal) → 구속조건 | 새 파이프라인. 회전체 전용 실행기로는 불가 | 캐스터급 |
| 5 | 카탈로그 도면(A·B·H 기호): 모델 번호로 규격표 조회 | 표 데이터 연결 | 카탈로그 |

4단계는 이 데모의 확장이 아니라 **다른 제품**이다. 회전체 파이프라인은 "한 부품 = 한 회전 프로파일" 이라는 계약 위에
서 있고, 조립도는 그 계약이 성립하지 않는다.

## 16. Part 2 를 "뷰 여러 개 → 부품 하나" 로 다시 만듦 (v43, 2026-08-17)

이전 Part 2 는 뷰마다 별개 부품을 만들었다. 실제 도면은 **한 부품을 여러 방향에서 그린 것**이므로 계약을 바꿨다:
`뷰 분할 → 방향(사람이 확정) → 치수 OCR 로 축척 → 각 뷰 압출의 교집합 → 뷰 재투영 정합`.

### 16.1 방향 (역할)
- 배치 기하로 추천: 정투상 뷰끼리는 부품 상자의 **범위가 같다**(윗면도 가로 = 정면도 가로). 겹침이 아니라 범위 일치(4%)로 본다.
  겹침 50% 로 했을 때 등각도가 윗면도 옆에 놓여 y 범위가 겹치는 바람에 윗면도가 정면도로 뽑혔다.
- 확정은 사람이: 오른쪽 **기준 정육면체**(정면·윗면·우측면 면 클릭) + 나머지 방향 버튼(좌·아래·뒤·등각·단면·상세·쓰지 않음).
  정투상 방향은 뷰 하나에만 준다(같은 방향을 다시 주면 이전 뷰는 "쓰지 않음").
- 3각법/1각법은 추천 배치에만 영향을 준다(각 뷰의 그림 자체는 같다).

### 16.2 치수 OCR → 축척 (`js/ocr-dims.js`, `vendor/tesseract/`)
- 문자 인식은 브라우저 안에서 돈다(워커·wasm·영어 데이터 8.8MB 를 vendor 에 둠). 숫자 토큰 + 픽셀 상자.
- 가는선 마스크에서 긴 수평·수직 런 = 치수선 후보. **화살촉은 선보다 굵어서 가는선 마스크에서 빠지므로**
  원 마스크에서 잉크를 따라 양쪽으로 늘리되, 그 픽셀을 지나는 세로 런이 길면(보조선·외형선) 멈춘다.
  처음엔 25mm 가 212px 로 재져 축척이 18% 틀렸다.
- 토큰 ↔ 가장 가까운 평행 치수선 → mm/px 후보 → 5% 안에서 맞는 후보가 가장 많은 값(다수결). 합의 수를 보여 준다.
- 실측: 예시 3장에서 축척 오차 0.3~0.5%, 합의 3/9 · 6/7 · 3/5. 못 읽으면 그때만 한 치수를 묻는다.

### 16.3 교집합 (`js/multiview.js`)
- 좌표 약속은 파일 머리에. 각 뷰는 자기 부품 상자를 세계 상자 [0,X]×[0,Y]×[0,Z] 에 맞춘다(도면 위 배치와 무관).
- 두 뷰가 같은 축을 정하면 차이를 "뷰 정합" 으로 보고한다(정면 우선).
- 잡은 함정 셋:
  1. **부품 상자를 픽셀 수가 가장 큰 성분으로 잡으면 안 된다** — 하우징 윗면도에서 안쪽 굵은 단차선 뭉치가 이겨 상자가 506px 로 잡혔다. 상자 넓이가 가장 큰 성분(외형선은 안의 모든 것을 품는다)으로.
  2. **1~2px 고리를 따라가면 바깥·안쪽 가장자리를 한 번에 돌아 스스로 겹치는 다각형**이 나와 캡 삼각분할과 구멍이 깨진다.
     고리+안쪽을 채운 덩어리의 경계(바깥 윤곽), 고리가 둘러싼 빈 공간의 경계(구멍)를 따라간다.
  3. **three r185 ExtrudeGeometry 는 바깥이 이미 시계방향이면 구멍 방향을 손보지 않는다** → 방향이 어긋난 구멍은 캡이 깨진다(부피가 커진다).
     바깥 반시계·구멍 시계로 맞춰 넘긴다(`orient`).
- 구멍 판정: 바깥 윤곽 안 + 속이 빈 닫힌 고리(cavity ≥ 45%) + 사각형 아님(area/box ≤ 0.9). 사각 고리는 단차·보스 모서리로 보고 무시(사각 창은 놓친다 — 안내에 적음).
- 침식 횟수: `round(굵기/2)−1` 은 4.8px 외형선을 0~1px 로 만들어 조각냈다(곡관 도면). `erosionIters`: ≤2→0, ≤6→1, ≤9→2, 그 외 3. Part 1 판독기도 같은 함수를 쓰고 가드 회귀는 그대로 통과(정상 60건 오거부 0).

### 16.4 검증: 뷰 재투영
만든 3D 의 삼각형을 각 뷰 평면에 정사영해 격자에 칠하고, 도면 쪽(바깥 윤곽 채움 − 구멍)과 IoU. 순수 JS 래스터라이저라 Node 테스트에서도 돈다.

| 예시 | 크기 오차 | 뷰 정합 | 단계 |
|---|---|---|---|
| L 브래킷 | 0.3 / 0.7 / 0.6 % | 윗 99.2 · 우 99.4 · 정 100 % | 1 |
| 베어링 하우징 | 0.6 / 0.6 / 0.4 % | 윗 97.8 · 정 97.5 · 우 100 % | 2 (근사) |
| 사각 플랜지 곡관 | — | 교집합으로 만들려 하지 않음(정투상 뷰 1개 → 판/미지원 안내) | 3 |

`tools/test-multiview.mjs` 가 이것을 고정한다. 예시 도면은 `tools/gen-part2-samples.mjs` 가 정답과 함께 만든다
(제도 관례대로: 보조선은 물체 가장자리부터, 화살촉 8×3, 3각법 배치, 등각 참고도 포함).

### 16.5 남은 것
숨은선(막힌 구멍·카운터보어) · 단면도에서 안쪽 형상 · 스윕(곡관) · 사각 창 구멍 · 서버 AI 로 방향 자동 확정(문자·표제란을 읽으면 가능).

## 17. Part 1 정리: 유형·시뮬 계획·해석·되돌아가기·내보내기 검증 (v44, 2026-08-17)

### 17.1 나사도 회전체인가
그렇다. 몸통은 회전체(나사부는 원통 + 규격 표기)이고 육각 머리·육각 소켓·D컷만 국부 형상(CSG)이다. Part 1 의 5종 나사 골든이 그 증거다.

### 17.2 부품 유형과 시뮬레이션 계획 (`js/part-types.js`)
클레비스 핀을 "자전" 시키니 아무 의미가 없었다(핀은 스스로 돌지 않는다). 유형별 계획을 두었다:
축·스핀들·롤러 = 자전, 핀 = 요크에 끼우기 + 분할핀, 부시·슬리브·스페이서 = 압입·끼우기, 볼트·스터드 = 체결.
- 유형은 사용자가 왼쪽에서 미리 고르거나(비우면) 사양에서 추정(`inferPartType`: 양 끝 나사 → 스터드, 나사부 45%+ 와 머리 → 볼트, 보어 → 부시/슬리브, 횡구멍 단순 원통 → 핀 …), 해석 결과가 있으면 그것을 따른다(사용자가 고른 것은 안 바꾼다).
- `analyzeMates(dsl, {partType})`: 핀이면 요크(두 귀 + 바닥) 상대 부품을 추가하고, 스스로 돌지 않는 유형은 자전 신뢰도를 0.3 으로 낮춘다.
- 시뮬을 켜면 계획을 보여 주고 기본 운동 버튼을 앞세운다. 기본이 분해·끼우기면 처음부터 60% 분해해 보여 준다.

### 17.3 부품 해석 (`tools/describe-prompt.mjs`, `/api/describe`, `tools/build-analysis.mjs`)
이전 "판독 노트"는 판독기의 계산 메모(Overall length is 51…)를 그대로 보여 준 것이라 설명이 아니었다.
지금은 **도면 이미지 + 판독 사양 + 도면 문자(OCR 토큰)** 을 함께 주고, 모든 항목에 근거(도면 문자 인용 / 사양 값 / 그림)를 달게 한다.
- 샘플 17종은 미리 만들어 `samples/<id>/analysis.json` 에 두었다(정적 데모 재생). 서버 모드에서 올린 도면은 브라우저 OCR 토큰과 함께 실시간으로 부른다.
- 결과 예(클레비스 핀): "분할핀 구멍이 있는 h11 공차의 클레비스 핀" · 핵심 형상 5개(근거 '⌀12 h11', '51' …) · 제작 유의(일반 공차 KS B ISO 2768-m 인용) · 알 수 없는 것(열처리·표면처리). 17종 유형 분류: 볼트 4 · 스터드 2 · 핀 1 · 부시 2 · 축 5 · 그 외 정확.

### 17.4 스텝퍼 되돌아가기
앞으로만 가던 스텝퍼가 이제 뒤로도 간다. 검증에서 3D CAD 를 누르면 검증 패널·오버레이만 걷어내고 3D 는 남는다. 2단계로 가면 3D·조립을 걷어내고 도면만, 1단계로 가면 사양까지 걷어낸다.

### 17.5 내보내기 검증 (외부 판독기로)

### 17.7 화면 언어 (한국어 · English)
오른쪽 위 토글로 바꾼다. 고른 언어는 `localStorage("vringon.lang")` 에 남고, 주소의 `?lang=` 이 있으면 그것이 이긴다(공유 링크용). 처음 온 사람은 브라우저 언어로 정한다.

원문이 한국어이므로 **한국어 문장이 그대로 사전 키**다. 호출부를 수백 군데 고치는 대신, 화면에 그려진 글자를 훑어 바꾸고(`TreeWalker`) 그 뒤에 생기는 내용은 `MutationObserver` 가 같은 규칙으로 바꾼다. 그래서 패널·토스트처럼 나중에 만들어지는 문장도 번역된다.

| 파일 | 무엇 |
|---|---|
| `js/i18n.js` | 엔진. `t()` · `setLang()` · `addDict()` · 토글 삽입 |
| `js/i18n-en.js` | 화면 사전 642항목 |
| `js/i18n-en-guide.js` | 안내 문서 본문 사전(분량이 커서 분리) |
| `js/guide-boot.js` | 안내 문서 시작점(본문 사전을 더한 뒤 켠다) |
| `tools/i18n-lint.mjs` | 중복 키·위험한 만능 패턴 점검(`--fix` 로 중복 정리) |

**함정 셋.** 겪은 것만 적는다.
1. `"{}. {}"` 같은 **만능 패턴**은 거의 모든 문장을 물어서 원문을 그대로 돌려준다. 번역이 안 될 뿐 아니라 `window.__i18nMissing` 에도 안 남아 원인을 못 찾는다. 지금은 lint 가 막는다.
2. **중첩 번역은 사전으로 못 한다.** `"윗면도 · 뷰 1"` 처럼 안쪽 조각이 변수면 반쪽만 영어가 된다. 조각마다 `t()` 를 부르도록 호출부를 나눠야 한다(part2.js 의 `roleName()`).
3. **보호 빌드는 진입점만 묶는다.** `index.html`·`guide.html` 이 직접 부르는 모듈은 `tools/deploy-docs.mjs` 의 진입점 목록에 넣어야 한다. 안 넣으면 배포본에서 404 가 나고 화면은 한국어로 남는다.

확인은 `?lang=en` 으로 열고 `window.__i18nMissing` 을 보면 된다. 비어 있으면 다 덮인 것이다. 지금 남는 것은 **도면에 적힌 한국어를 AI 가 인용한 문장**뿐이다(`Drawing text '⌀4 관통'`) — 도면 자체가 한국어이므로 그대로 두는 것이 맞다.

### 17.8 예시 도면 확장과 라이브러리 쌍 데이터
라이브러리 카드 한 장이 **쌍 하나**가 되었다. 왼쪽은 올리는 도면, 오른쪽은 그 도면에서 나온 3D 다.
오른쪽 그림의 출처를 카드에 그대로 적는다 — `판독 결과`(그 샘플의 실제 AI 판독 `extracted.json` 으로 만든 것) 또는 `정답 사양`(판독본이 없어 골든으로 만든 것). 지금 25종 중 17 · 8 이다.

**그림은 어떻게 굽나.** `tools/render-thumb.mjs` 가 브라우저 없이 삼각형을 직접 래스터화한다(z 버퍼 + 램버트, 3배 수퍼샘플링, 화면과 같은 파랑). WebGL 없이 도는 것이 목적이라 얇게 짰다. Part 2 는 `tools/part2-build.mjs` 가 화면과 같은 순서(뷰 나누기 → 역할 → 치수 → 교집합)를 Node 에서 밟아 같은 결과를 만든다.

**순서 주의.** `build-samples.mjs` 는 `samples/index.json` 을 새로 쓰므로 쌍 정보(`files.result`·`result_from`)가 지워진다. 반드시 이어서 `render-thumb.mjs` 를 돌린다. 잊으면 `tools/test-pairs.mjs` 가 잡는다(결과 그림이 도면보다 오래된 것도 잡는다).

**Part 1 골든 8종 추가 (17 → 25).** 부품 유형 선택기의 유형마다 예시가 최소 한 장은 있게 채웠다. `flange` 는 그전까지 예시가 하나도 없었다.
`hub-flange`(플랜지) · `dowel-pin` · `taper-pin`(핀) · `shoulder-bolt` · `knurled-knob`(널링 표기를 쓰는 유일한 샘플) · `piston-rod`(결합부가 가장 많다) · `valve-spool`(홈 3개) · `shaft-collar`.

**Part 2 예시 3종 추가 (3 → 6).** `plate`(면+두께 두 뷰) · `channel`(안쪽이 파인 ㄷ 단면) · `block`(정면 보어, 2단계). 6종 모두 `tools/test-multiview.mjs` 통과.

#### 겪은 것 — 짧고 굵은 부품이 판독기의 약점을 드러냈다
플랜지를 넣자마자 세 가지가 터졌고, 셋 다 판독기 자체의 문제였다.

1. **단면도 원을 정면도로 골랐다.** 정면도는 "가장 큰 성분" 으로 고르는데, 짧고 굵은 부품에서는 옆의 A-A 원이 정면도보다 크다. 원의 윤곽을 축 방향 외형으로 읽어 IoU 0.48. → `circleness()` 로 원을 후보에서 **미리** 뺀다. 고른 뒤에 바꾸는 방식으로 먼저 짰더니 전단면도의 위·아래 반쪽 짝짓기가 어긋나 해상도마다 결과가 달랐다. 전체 IoU 0.972 → 0.992.
2. **막던 것을 안 막게 됐다.** 원을 빼자 볼트 원 도면(`negative-flange-3view`)이 옆모습만 읽혀 통과해 버렸다. 원형 투상 신호에 기대 막고 있었던 것이다. → 뺀 원 **안에 작은 구멍이 셋 이상**이면 볼트 원으로 보고 멈춘다(`bolt_circle`). 볼트 원 구멍은 원래 만들지 못하는 형상이라 멈추는 게 맞다.
3. **멀쩡한 도면을 되돌려보냈다.** 1800px 에서 전단면도의 한쪽 반쪽이 조각나 짝을 못 찾고 "위아래가 다르다" 며 거부했다(선 굵기가 3px 이라 침식 한 번에 끊긴다). 침식을 건너뛰게 바꿔 봤더니 실패가 1건에서 6건으로 늘어 되돌렸다. → 반대쪽이 **여러 조각이면 모아서 한 반쪽으로** 본다. 스캔 도면에서도 흔한 경우라 판독기 전체가 튼튼해졌다. 아울러 허브 ⌀34 → ⌀40 (키홈 밑 살 3 → 6): 도면에서 그렇게 얇은 곳은 애초에 좋은 설계가 아니다.

정상 84건 오거부 0 · 음성 3종 모두 차단 · 회귀 5종(조립·내보내기·입력 차단·다시점·쌍) 통과.

### 17.9 반응형 — 좁은 화면의 작업 화면
폰으로 데모 링크를 열어 본 사람이 하는 일은 정해져 있다: 샘플을 고르고 · 3D 가 되는 것을 보고 · 돌려 보고 · 판독과 해석을 훑고 · 내려받는다. 세 칸을 그대로 두면 3D 가 240px 로 찌그러지고(768px), 위아래로 쌓으면 칸마다 210px 라 아무것도 못 읽는다(375px). 둘 다 실측.

**설계.** 1024px 아래에서는 **한 번에 한 칸**(도면 · 3D · 결과)만 꽉 채워 보여 주고 아래 탭으로 옮긴다. 탭은 흐름을 따라 저절로도 넘어간다 — 샘플을 고르면 3D 로, 판독·3D·검증이 끝나면 결과 탭에 점이 켜진다. Part 2 는 오른쪽이 방향·치수·만들기라 흐름이 도면 → 설정 → 3D 다. 1280 아래에서는 칸만 좁힌다. `js/panes.js` 가 이 전환을 맡고, 넓은 화면에서는 아무 일도 하지 않는다.

3D 위에 떠 있는 것들은 좁은 곳에서 다시 배치했다: 단계 표시는 왼쪽 위(가운데 정렬 + translate 를 두면 왼쪽 밖으로 나갔다), 보기 버튼 다섯은 한 줄로 가로 스크롤(두 줄로 접히면 3D 위 1/4 을 덮었다), 시뮬 조작판은 폭을 다 쓰는 두 줄(세로로 쌓이면 187px). 위 막대는 줄바꿈 대신 가로 스크롤(세 줄로 접혔었다). 샘플 칩은 여섯 장만(25장이 2,000px 을 차지해 올리기 상자를 밀어냈다). 첫 방문 안내는 대상이 사는 칸으로 먼저 옮긴다.

**함정 셋.**
1. 배포 빌드의 버전 해시가 js/ 와 index.html 만 보고 있어 **CSS 만 바뀐 배포가 같은 버전으로 나가** 캐시에 갇혔다. `<link>` 에도 `?v=` 를 붙이고 해시에 CSS · 페이지 넷을 넣었다.
2. 좁은 화면 규칙 하나(`.seg button { min-height }`)가 위 막대의 언어 토글에도 걸려 "한국어" 가 세 줄이 됐다. 토글은 `flex:none; width:max-content` 로 못박았다.
3. 화면 밖 탭에서는 **rAF 가 멈춘다.** 칸을 바꿀 때 보내던 resize 와 안내 카드 배치가 rAF 에 걸려 있어 자동화 검증에서 안 움직였다. `setTimeout(…, 0)` 으로 바꿨다(사용자에게는 차이 없다).

375 · 768 · 1024 · 1280 에서 네 페이지 모두 가로 넘침 0. 회귀 5종 통과.

### 17.10 Part 3 — 프롬프트와 이미지에서 3D
진입 화면이 세 갈래가 되었다. Part 3 는 **도면이 없을 때** 쓰는 갈래로, 한 줄 설명이나 사진 한 장에서 부품 트리를 세우고 파트를 분리해 본다. 일부러 여기까지만 한다 — 내보내기·검증·시뮬은 Part 1·2 의 몫이고, 이 화면이 보여 줄 것은 "부품이 트리로 나뉘어 나온다" 하나다.

**사양 형식은 [img2threejs](https://github.com/img2threejs/img2threejs) (Apache-2.0) 의 ObjectSculptSpec 을 따른다.** 그 프로젝트의 여덟 단계 조각 파이프라인이 아니라 브라우저에서 조립하는 데 필요한 부분집합만 쓴다: `componentTree` · `attachment`(부모 소켓) · `materials` · `sockets`. 코드는 가져오지 않았고 형식만 참고했으며, 출처는 배포본 `LICENSES.txt` 에 들어간다.

| 파일 | 무엇 |
|---|---|
| `js/sculpt-spec.js` | 사양 → THREE.Group. 검사 · 배치 규칙 · 파트 목록 |
| `js/sculpt.js` | 화면. 입력 · 파트 목록 · 분리 |
| `tools/sculpt-prompt.mjs` | 사양 작성 프롬프트와 스키마 (서버 전용) |
| `tools/gen-sculpt-samples.mjs` | 예시 3종(스탠드·머그·의자) |
| `tools/test-sculpt.mjs` | 사양 검사 · 부품 접합 · 파트 분리 회귀 |
| `/api/sculpt` | 라이브 생성. 키는 서버에만 |

**배치 규칙이 이 기능의 전부다.** 소켓과 위치를 둘 다 더하면 부품이 두 번 옮겨져 떠 버린다(실측: 의자 다리 넷이 좌판 바깥으로 밀려 나갔다). 규칙 하나로 못박았다: ① `localStart` 가 있으면 그 점이 소켓에 닿게 ② 없고 위치가 주어졌으면 그 위치를 그대로 ③ 둘 다 없으면 소켓에서 법선 방향으로 제 몸 절반만큼. `tools/test-sculpt.mjs` 가 자식 상자와 부모 상자 사이 틈을 재서 이것을 고정한다.

#### 겪은 것 — 프롬프트가 스키마에 끌려간다
1. **스키마 설명의 예시를 물체로 착각했다.** `id` 설명에 "예: desk-lamp" 라고 적었더니, 프라이팬을 요청해도 `id: "desk-lamp"` 를 쓰고 그에 맞춰 책상 램프를 만들었다. 스키마 설명에는 값의 **종류**만 적는다.
2. **배열 개수 제한이 변환에서 사라졌다.** `minItems: 2` 가 공급자 형식으로 옮겨지지 않아 부품이 하나뿐인 트리가 왔다(파트 분리 데모인데 나눌 것이 없다). 변환에 `minItems`·`maxItems` 를 넣고, 서버에 수리 루프를 뒀다.
3. **없는 소켓을 가리켰다.** `attachment.parentSocket` 이 부모에 없는 소켓을 가리켜 등받이와 다리가 제자리에 안 붙었다. 수리 루프가 문제를 적어 한 번 되짚게 한다(실측 5건 교정).
4. **`parent` 를 문자열 `"null"` 로 썼다.** 조립기가 부모 없음으로 보지 못해 통째로 실패했다. `parentOf()` 로 정리한다.
5. **사전을 늦게 더하면 이미 그려진 글자가 안 바뀐다.** `addDict` 를 모듈 맨 위로 올렸다(실측: 예시 칩·프롬프트 버튼 7개가 한국어로 남았다).

라이브 실측: 프라이팬 2파트 7.3초, 의자 6파트 12.7초. 예시 3종은 서버 없이 돈다. 회귀 6종 통과.
